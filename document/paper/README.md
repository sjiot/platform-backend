## 논문의 중심 내용

1. 서버 처리 지연을 구간별로 나눠 병목을 찾는다.
2. 병목을 줄이고 같은 조건에서 전후를 비교한다.
3. 통신 개선과 배정 정책 개선의 효과를 나눠서 보고한다.

통신 개선은 서버 제어 지연을 줄이고, 처리량과 주문 대기는 배정 정책의 영향을 더 크게 받을 것으로 예상한다. 둘 다 아직 검증 전이다.

## 추천 범위

| 구분 | 후보 | 이유 |
|---|---|---|
| 네트워크 | A. Mobius 연결 재사용 | 변경이 작고 외부 통신 구간을 직접 줄일 수 있다 |
| 네트워크 | C. 기록용 CIN 비동기화 | 배정 요청이 기다리는 Mobius 호출 수를 줄인다 |
| 알고리즘 | E. `SKIP_BLOCKED` 정책 비교 | 플래그가 이미 있어 조건을 나누기 쉽다 |

B(Redis 파이프라인)는 왕복 수 감소가 분명해 함께 다룰 수 있다. Redis가 서버와 가까우면 시간 절감은 작을 수 있으므로 측정 후 포함 여부를 정한다.

## 데이터 상태

| 자료 | 상태 |
|---|---|
| 호출 경로별 Redis 왕복 수 | 가짜 Redis로 1회 측정. 리눅스에서 다시 확인 필요 |
| 구간별 지연 시간, 단계별 시간 | 측정 코드만 있고 실측 데이터 없음 |
| 개선 전후 비교 | 없음 |
| 배정 정책 비교 | 없음 |

**실측 전의 수치를 결과로 쓰지 않는다.** 문서의 `[측정 필요]`는 아직 값이 없다는 뜻이다.

## 저장소 관련 주의

`.gitignore`가 `tests/`, `debug/`, `logs/`를 제외한다. 측정 도구는 `infra/`에 있어 서버에 함께 올라가지만, 테스트와 원본 로그는 git에 남지 않으므로 논문 제출 전까지 별도로 백업해야 한다.

`README.md`와 `Dockerfile`은 아직 Cloud Run 배포 기준이다. 논문에는 실제 리눅스 서버 구성을 적는다.
