# 포스터 구성

제출 학회의 양식과 분량에 맞춰 조정한다. 제목과 수치는 실험 후 확정한다.

## 제목 후보

- oneM2M 기반 키캡 조립 IoT 라인 제어 서버의 통신 지연 분석 및 개선
- oneM2M 기반 소량 맞춤 생산 라인의 주문 배정과 제어 통신 효율 개선

## 구성

### 1. 서론

- 소량 맞춤 조립 라인은 여러 장비와 서버가 Mobius를 거쳐 상태를 주고받는다.
- 기존 구조에서 서버는 콜백 처리 중에 Redis와 Mobius를 순서대로 호출한다.
- 이 연구는 제어 지연을 구간별로 나누고, 통신과 배정 정책을 개선해 효과를 측정한다.

### 2. 시스템 구성

- 그림 1: 키오스크, 서버, Redis, Mobius, 장비의 구성과 통신 경로
- 주문 단계와 고장 감지 구조 요약 ([01-system.md](01-system.md))

### 3. 성능 분석

- 측정 방법과 지표 정의
- 그림 2: 주문 단계별 소요 시간 누적 막대
- 표 1: 구간별 p50, p95, 실패율
- 표 2: 경로별 Redis 왕복 수와 CIN 수

### 4. 개선 구현

- Mobius 연결 재사용
- 기록용 CIN 비동기화와 `cnt_process` 동기 유지 이유
- 막힌 주문 건너뛰기 배정
- 실제 측정에서 효과가 확인된 항목만 넣는다.

### 5. 실험 결과

- 표 3: 실험 환경 ([04-experiments.md](04-experiments.md) 1장)
- 그림 3: 개선 전후 p50/p95 비교
- 표 4: 재고 시나리오별 처리량과 대기 시간

### 6. 결론

- 줄어든 구간과 그 크기
- 처리량에 영향을 준 요인
- 한계와 향후 과제

## 표현 주의

| 피할 표현 | 쓸 표현 | 이유 |
|---|---|---|
| 주문 처리 시간 N% 단축 | 콜백 처리 p95 N% 감소 | 통신 개선이 기계 시간을 줄이지는 않는다 |
| 네트워크 속도 개선 | 연결 비용과 호출 수 감소 | 망 자체를 개선한 것이 아니다 |
| 실시간 처리 | 측정된 지연 범위 제시 | 근거 없는 수식어다 |
| 시뮬레이션 결과를 실기 결과처럼 서술 | "실측 시간 분포를 넣은 시뮬레이션 결과" | 실험 환경을 구분해야 한다 |
| 스텁 지연 결과를 네트워크 측정처럼 서술 | "지연 N ms를 가정한 부하 시험" | 스텁의 지연은 입력값이다 |

## 한계로 적을 내용

- 공용 Mobius 서버의 부하를 통제할 수 없다.
- 실제 장비 실험의 표본이 적다.
- 시뮬레이터의 기계 시간은 측정값 또는 가정값이다.
- 대기열이 최대 3건이고 소규모 라인이어서 대규모 라인에 그대로 일반화할 수 없다.
- 구독 전달 지연의 정확도는 시계 동기화에 의존한다.

## 분량이 부족할 때

1. 범위를 A와 E로 줄인다.
2. 실기 데이터가 부족하면 단계 분해를 "시범 운행 N건"으로 명시한다.
3. 개선 효과가 작으면 그 결과를 그대로 쓰고, 측정으로 찾은 실제 병목을 결론으로 삼는다.
